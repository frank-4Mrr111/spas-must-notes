Topic 1: Introduction to Information Systems

Estimated time: ~30 minutes | Objectives: Define IS, name 5 components, distinguish Data vs Information, name types, explain why insurance needs systems.

An Information System is people, data, software, hardware, and procedures working together to collect data, turn it into information, and help people decide.

  1. Hardware — computers, servers. Example: server holding 100,000 policies.
  2. Software — Excel, policy system.
  3. Data — raw facts: name, age, sum assured.
  4. People — clerks enter, actuaries use, managers decide.
  5. Procedures — rules: enter new policy within 24 hours, check age, save, back up.

Data vs Information: Data = raw facts, e.g. 30, 100000, 2000. Information = data with meaning, e.g. "A 30-year-old with sum assured 100,000 pays premium 2,000 per year." Flow: Data → Processing → Information → Decision.

Types: TPS records daily work. MIS produces reports. DSS helps what-if. EIS gives short summaries for senior managers.

Common exam mistake: Saying "a computer system" and stopping. Always name components + give insurance example.

Topic 2: Data, Databases and Data Management

Estimated time: ~30 minutes | Objectives: Define database, explain table / field / record / key, explain why Name cannot be Primary Key, write query, explain data management.

A database is organised data stored so you can search it, update it, and protect it quickly.

  • Table — one topic, e.g. Policies table.
  • Field — one type of data, e.g. Age.
  • Record — one full item, e.g. one policy.
  • Primary Key — unique ID, never repeated. Name cannot be key — two people share name, name can change.
  • Foreign Key — key from another table to link tables.
  • Query — question to database, e.g. show Age > 60.

Worked Example: Policies table, filter Age > 60. If 500 rows and 40 are over 60, system shows 40 rows.

Common exam mistake: Confusing table with database. Table = one list. Database = many linked tables + rules.

Topic 3: Spreadsheets for Actuaries

Estimated time: ~35 minutes | Objectives: Explain spreadsheet, use cell references, write SUM, AVERAGE, MAX, MIN, COUNT, IF, VLOOKUP, PMT, follow good practice.

A spreadsheet is a grid where you type data, write formulas, and computer calculates automatically. A cell is one box, e.g. B2. A formula always starts with =.

Golden rule: Always use cell references, never type numbers inside formula. Wrong: =2500+5000. Right: =SUM(B2:B5).

=SUM adds. =AVERAGE adds then divides. =MAX / =MIN largest / smallest. =COUNT how many. =IF(condition, if-true, if-false). =VLOOKUP finds value in table.

Worked Example — Total: Claims C2:C4 = 12000, 18000, 15000. Formula =SUM(C2:C4). = 45000.

Worked Example — Average: Premiums 2000, 3000, 5000. Sum = 10000. Count = 3. Average = 100003 = 3333.33. Formula: =AVERAGE(B2:B4).

Common exam mistake: Writing answer without formula. In spreadsheet questions, formula IS the answer.

Topic 4: Actuarial Software and Programming Basics

Estimated time: ~30 minutes | Objectives: Explain actuarial software, explain Input → Process → Output, explain why software beats hand calc, write steps, choose right tool.

Actuaries use Excel, R, Python, and specialist systems like Prophet or MoSes. A program is a list of clear steps computer follows exactly.

Input → Process → Output: Input = what you give (age, sum). Process = what it does (premium = sum × rate). Output = what you get (premium). If input is wrong, output is wrong. "Garbage In, Garbage Out".

Why software beats hand: Speed — 100,000 policies in seconds. Consistency — same steps. What-if — change rate, all update. Audit — you can check steps.

Worked Example: Step 1: Input sum = 100,000, rate = 0.02. Step 2: Process: premium = 100,000 × 0.02 = 2,000. Step 3: Output: premium = 2,000.

Common exam mistake: Saying software "decides" premium. Software does not decide. Actuary decides method, rate. Software only follows them.

Topic 5: Data Security, Ethics and Privacy

Estimated time: ~30 minutes | Objectives: Define security, privacy, ethics, list ways to protect data, judge real situation, explain what to do when asked for data you should not share.

Actuarial data is sensitive: names, ages, health, money, ID numbers. Security = protecting from loss / theft. Privacy = only collecting / using what you need. Ethics = using fairly.

  1. Passwords + access control — only staff who need data can open it.
  2. Backup — copy in another safe place.
  3. Do not share / download to personal phone / WhatsApp — work inside system.
  4. Encryption — scramble data so thief cannot read without key.
  5. Updates + antivirus — keep software updated.

Worked Example: Clerk shares client list on WhatsApp to "work from home". That is breach — even if nothing bad happens yet. Right way: access system with password, no download, no sharing.

Common exam mistake: Listing "password" and stopping. Always give method + what it protects against.

Topic 6: Management Information Systems and Decision Support

Estimated time: ~30 minutes | Objectives: Define MIS, distinguish raw data vs MIS report, explain good report, calculate profit, explain Decision Support / what-if.

A Management Information System turns raw data into reports for managers. Raw data = 100,000 rows. MIS report = one page: total premiums, total claims, profit, new policies.

Good MIS report: Accurate, Timely, Clear, Relevant, Comparable.

Decision Support / what-if: Manager asks "What if...?" System recalculates. Example: "What if claims rise 10%?" New claims = old × 1.10, new profit = premiums − new claims.

Worked Example — Profit: Premiums = 14,500,000, Claims = 10,000,000. Profit = 14,500,000 − 10,000,000 = 4,500,000.

Common exam mistake: Saying MIS is "a report". MIS is the system that produces the report. Report is output.
