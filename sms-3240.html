Topic 1: Introduction to Information Systems

Objectives: By the end, you can define an Information System, name and explain its 5 components with insurance examples, distinguish Data from Information, name types of systems, and explain why insurance needs systems.

An Information System is people, data, software, hardware, and procedures working together to collect data, turn it into information, and help people make decisions. No one part works alone. Hardware without software does nothing. Software without data has nothing to process. Data without people to use it is useless.

The 5 components:

  1. Hardware — computers, phones, servers. They store and run the system. In insurance: the computer that runs the policy system, the server that holds 100,000 policies.
  2. Software — programs such as Excel or a policy system. It processes the data. It calculates premium, searches for a policy, prints a report.
  3. Data — raw facts: name, age, sum assured, premium paid, claim amount. Data on its own has no meaning until it is organised.
  4. People — the users, managers, and IT staff. Clerks enter data. Actuaries use the information. Managers decide from the reports. IT staff keep the system running.
  5. Procedures — the rules and steps everyone follows. Example: enter a new policy within 24 hours, check age and sum assured, save, back up. Without procedures, two clerks do the same job differently and the data becomes messy.

Data and Information:

Data is raw facts with no meaning yet. Example: 30, 100000, 2000. You see numbers, but you do not know what they mean.

Information is data organised with meaning and context. Example: "A 30-year-old with sum assured 100,000 pays premium 2,000 per year." Now you understand it and you can act on it.

The flow is: Data → Processing (sorting, adding, calculating) → Information → Decision. Example: data from 1,000 policies is added by the system → information: total premiums = 2,000,000 → manager decides: we have enough to pay expected claims.

Types of Information Systems: Transaction Processing System (TPS) — records daily work, e.g. issuing policies, receiving premiums. Management Information System (MIS) — produces reports for managers. Decision Support System (DSS) — helps with what-if questions, e.g. what if claims rise 10%? Executive Information System (EIS) — short summaries for senior managers.

Why insurance needs systems: Speed — find a policy in seconds, not 30 minutes in paper files. Accuracy — a computer does not forget or mis-add when tired. Memory — a system remembers 100,000 policies, a human cannot. Reports — a manager can see total premiums, total claims, and profit in one report. Control — only authorised staff can see or change data.

Common exam mistake: Saying "a computer system" and stopping. In exams, always name the components, give an insurance example for each, and explain what happens if one component is missing.

Topic 2: Data, Databases and Data Management

Objectives: By the end, you can define a database, explain table / field / record / key, explain why Name cannot be a Primary Key, explain Foreign Key, write a query / filter, and explain how to manage data.

A database is organised data stored so you can search it, update it, and protect it quickly. Think of a smart filing cabinet — not a pile of papers, but labelled drawers where you can find anything in seconds.

Key words:

  • Table — one topic, e.g. Policies table. One table per topic: Policies, Claims, Clients.
  • Field / Column — one type of data, e.g. Name, Age, Sum Assured.
  • Record / Row — one full item, e.g. one policy: P-102, Frank, 30, 100000.
  • Primary Key — a unique ID for each row, never repeated, never blank. Example: Policy Number. Two people can share a name, and a person can change their name, so Name cannot be a key. Policy Number never changes and never repeats.
  • Foreign Key — a key from another table used to link tables. Example: Policy Number in the Claims table links a claim back to its policy.
  • Query / Filter — a question to the database. Example: show all policies where Age is greater than 60. The system shows only those rows.

Worked example: Policies table has PolicyNo, Name, Age. You need policies where Age is greater than 60. You filter the Policies table where Age is greater than 60 and show PolicyNo, Name, Age for those rows only. If the table has 500 rows and 40 are over 60, the system shows 40 rows, not 500.

Why databases beat paper and spreadsheets for large data: Many people can use it at the same time. You can search in seconds. You can stop two people changing the same record at once. You can control who sees what. A spreadsheet is good for calculations, but it is easy to overwrite, hard to control, and slow when 100,000 rows grow.

Data management: Enter data correctly — check age, sum, dates. Update when it changes — address, premium, beneficiary. Back up — keep a copy in another safe place, so if the computer dies, the data lives. Control access — only staff who need data can open it. Clean data — remove duplicates, fix errors, fill missing fields where possible.

Common exam mistake: Confusing a table with a database. A table is one list. A database is many linked tables plus the rules to keep them correct.

Topic 3: Spreadsheets for Actuaries

Objectives: By the end, you can explain what a spreadsheet is, use cell references correctly, write SUM, AVERAGE, MAX, MIN, COUNT, IF, VLOOKUP, PMT, and follow good spreadsheet practice.

A spreadsheet is a grid of rows and columns, such as Excel or Google Sheets, where you can type data, write formulas, and the computer calculates automatically. A cell is one box, e.g. B2 means column B, row 2. A formula always starts with =.

The golden rule: Always use cell references, never type numbers inside a formula. Wrong: =2500+5000. Right: =SUM(B2:B5). If one premium changes from 2500 to 3000, the wrong formula still gives the old total. The right formula updates automatically because it reads the cells.

Formulas you must know:

  • =SUM(B2:B5) — adds all numbers from B2 to B5.
  • =AVERAGE(B2:B4) — adds them, then divides by how many there are.
  • =MAX(B2:B5) / =MIN(B2:B5) — largest / smallest value in the range.
  • =COUNT(B2:B5) — how many numbers are in the range.
  • =IF(condition, value-if-true, value-if-false) — e.g. =IF(Age>60, "Senior", "Young").
  • =VLOOKUP — finds a value in a table, e.g. finds the premium rate for a given age.
  • =PMT — calculates a loan / annuity payment from rate, periods, and present value.

Worked example — total: Claims in C2:C4 are 12000, 18000, 15000. The formula for total is =SUM(C2:C4). The computer adds 12000 + 18000 + 15000 = 45000. You write the formula, not just 45000.

Worked example — average: Premiums are 2000, 3000, 5000. Step 1: Sum = 2000 + 3000 + 5000 = 10000. Step 2: Count = 3. Step 3: Average = 10000 / 3 = 3333.33. Formula: =AVERAGE(B2:B4).

Good spreadsheet practice: Label every column. Keep inputs in one place, calculations in another, results clearly labelled. Do not mix numbers and formulas in the same cell without a label. Check totals by a second method. If a result looks impossible, e.g. average premium higher than the highest premium, it is wrong.

Common exam mistake: Writing the answer without the formula. In spreadsheet questions, the formula is the answer. Always show the formula you used.

Topic 4: Actuarial Software and Programming Basics

Objectives: By the end, you can explain what actuarial software is, explain Input → Process → Output, explain why software beats hand calculation, write steps to solve a problem, and choose the right tool for a job.

Actuaries use software to model many policies at once: Excel, R, Python, and specialist actuarial systems such as Prophet or MoSes. A program is a list of clear steps the computer follows exactly, every time, without getting tired.

Input → Process → Output: Input is what you give the computer — age, sum assured. Process is what it does — premium = sum × rate. Output is what it gives you — premium. If input is wrong, output is wrong. The computer does not know, it just follows steps. That is "Garbage In, Garbage Out".

Why software beats hand calculation: Speed — 100,000 policies in seconds; by hand it would take months. Consistency — same steps every time, no tired mistakes. What-if — change the rate from 0.02 to 0.03, press Enter, all premiums update; by hand you start again. Audit — you can check the steps, test with a few policies, and re-run.

Worked example: Calculate premium for one policy. Step 1: Input sum assured = 100,000, rate = 0.02. Step 2: Process: premium = 100,000 × 0.02 = 2,000. Step 3: Output: premium = 2,000. In Python that is: premium = 100000 * 0.02. The actuary decided the rate. The computer just multiplied.

Choosing the right tool: Spreadsheet — quick checks, small models, teaching. R / Python — large data, repeating the same calculation many times, graphs. Specialist actuarial software — full company models, reserves, solvency, many scenarios at once. In exams, do not say "use a computer" — name the tool and say why it fits that job.

Common exam mistake: Saying software "decides" the premium. Software does not decide. The actuary decides the method, the assumptions, and the rate. Software only follows them.

Topic 5: Data Security, Ethics and Privacy

Objectives: By the end, you can define security, privacy, and ethics, list and explain ways to protect data, judge a real situation, and explain what to do when asked for data you should not share.

Actuarial data is sensitive: names, ages, health, money, ID numbers. Security is protecting it from loss or theft. Privacy is only collecting and using what you need, only sharing with who needs it. Ethics is using it fairly, even when you could get away with unfair use.

Ways to protect data:

  1. Passwords and access control — only staff who need data can open it. A clerk sees policies, a manager sees reports, IT sees the system — not everyone sees everything.
  2. Backup — keep a copy in another safe place, so if a computer dies or is stolen, the data lives.
  3. Do not share or download to personal phone or 【entity-WhatsApp¦canonical_name=WhatsApp】 — work inside the system, not outside it.
  4. Encryption — scramble data so even if it is stolen, a thief cannot read it without the key.
  5. Updates and antivirus — keep software updated, do not open suspicious links or files.

Ethics and privacy in practice: Collect only what you need for the job. Use data only for the purpose the person agreed to. Do not use health data to refuse someone unfairly. Do not sell or share client lists. Keep a record of who accessed what. If you are unsure, ask your manager — do not guess.

Worked example: A clerk shares a client list on 【entity-WhatsApp¦canonical_name=WhatsApp】 to "work from home". That is a breach — even if nothing bad happens yet. The right way: access the system with a password, no download, no sharing, work inside the system.

Another example: A colleague asks for a client's health data "just to check". The correct answer is No. You do not have the client's permission for that purpose. You do not know if the colleague needs it for work. If it leaks, the client is harmed and the company is blamed. The right way: the colleague asks the manager, the manager checks if access is needed, then gives limited access through the system, with a record.

Common exam mistake: Listing "password" and stopping. In exams, always give the method and explain what it protects against — e.g. password stops unauthorised access, backup protects against loss, encryption protects against theft.

Topic 6: Management Information Systems and Decision Support

Objectives: By the end, you can define MIS, distinguish raw data from an MIS report, explain what makes a good report, calculate profit, and explain Decision Support / what-if.

A Management Information System is a system that turns raw data into reports for managers. Raw data is 100,000 rows, too many to read. An MIS report is one page: total premiums, total claims, profit, number of new policies, number of claims. A manager reads the report, not the rows.

What makes a good MIS report: Accurate — numbers must be correct. Timely — a report that arrives a month late is useless. Clear — one page, labelled, no clutter. Relevant — only what that manager needs. Comparable — this month vs last month, this year vs last year, so the manager can see a trend.

Decision Support and what-if: A manager asks "What if...?" and the system recalculates. Example: "What if claims rise 10%?" System: new claims = old claims × 1.10, new profit = premiums − new claims. Manager sees the new profit and decides: raise premiums, cut costs, or keep as is.

Worked example — profit: Premiums = 14,500,000, Claims = 10,000,000. Profit = Premiums − Claims = 14,500,000 − 10,000,000 = 4,500,000. Formula: Profit = Total Premiums − Total Claims.

Worked example — raw data vs report: Raw data table: 100,000 rows, each row one policy. MIS report: 5 lines — Total Policies: 100,000, Total Premiums: 20,000,000, Total Claims: 12,000,000, Profit: 8,000,000, New Policies This Month: 500. Difference: raw data is detail, MIS is summary for decision.

Common exam mistake: Saying MIS is "a report". MIS is the system that produces the report. The report is the output. In exams, name the system, name the report, and give an example of a decision made from it.
