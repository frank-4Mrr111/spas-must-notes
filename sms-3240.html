Topic 1: Introduction to Information Systems

Estimated time: ~30 minutes  |  Objectives: Define IS, name 5 components with insurance examples, distinguish Data vs Information, name types, explain why insurance needs systems.

An Information System is people, data, software, hardware, and procedures working together to collect data, turn it into information, and help people decide. No one part works alone.

  1. Hardware — computers, phones, servers. Example: server holding 100,000 policies.
  2. Software — Excel, policy system. It calculates premium, searches policy.
  3. Data — raw facts: name, age, sum assured, premium paid.
  4. People — clerks enter, actuaries use, managers decide, IT keeps system running.
  5. Procedures — rules: enter new policy within 24 hours, check age, save, back up.

Data vs Information: Data = raw facts with no meaning yet. Example: 30, 100000, 2000. Information = data with meaning. Example: "A 30-year-old with sum assured 100,000 pays premium 2,000 per year." Flow: Data → Processing → Information → Decision.

Types: TPS records daily work (issuing policies). MIS produces reports for managers. DSS helps what-if questions. EIS gives short summaries for senior managers.

Why insurance needs systems: Speed — find policy in seconds. Accuracy — no tired mistakes. Memory — remembers 100,000 policies. Reports — total premiums, claims, profit in one report. Control — only authorised staff can see data.

Common exam mistake: Saying "a computer system" and stopping. Always name components + give insurance example + say what happens if one is missing.

Topic 2: Data, Databases and Data Management

Estimated time: ~30 minutes  |  Objectives: Define database, explain table / field / record / key, explain why Name cannot be Primary Key, write query / filter, explain data management.

A database is organised data stored so you can search it, update it, and protect it quickly. Not a pile of papers — labelled drawers where you find anything in seconds.

  • Table — one topic, e.g. Policies table.
  • Field — one type of data, e.g. Age.
  • Record — one full item, e.g. one policy: P-102, Frank, 30, 100000.
  • Primary Key — unique ID, never repeated, never blank. Example: Policy Number. Name cannot be key — two people share name, name can change.
  • Foreign Key — key from another table to link tables. Example: Policy Number in Claims table links claim to policy.
  • Query / Filter — question to database. Example: show all policies where Age > 60.

Worked Example: Policies table has PolicyNo, Name, Age. Filter Age > 60. If 500 rows and 40 are over 60, system shows 40 rows, not 500.

Why database beats paper / spreadsheet for large data:[STRIPPED]b> Many people can use at same time. Search in seconds. Stop two people changing same record. Control who sees what. Spreadsheet is good for calculations, but easy to overwrite, hard to control, slow at 100,000 rows.

Data management: Enter correctly — check age, sum, dates. Update when it changes. Back up — copy in another safe place. Control access. Clean data — remove duplicates, fix errors.

Common exam mistake: Confusing table with database. Table = one list. Database = many linked tables + rules.

Topic 3: Spreadsheets for Actuaries

Estimated time: ~35 minutes  |  Objectives: Explain spreadsheet, use cell references, write SUM, AVERAGE, MAX, MIN, COUNT, IF, VLOOKUP, PMT, follow good practice.

A spreadsheet is a grid of rows and columns where you type data, write formulas, and computer calculates automatically. A cell is one box, e.g. B2. A formula always starts with =.

Golden rule: Always use cell references, never type numbers inside formula. Wrong: =2500+5000. Right: =SUM(B2:B5). If premium changes, wrong formula stays old, right formula updates.

=SUM(B2:B5) adds. =AVERAGE(B2:B4) adds then divides by how many. =MAX / =MIN largest / smallest. =COUNT how many numbers. =IF(condition, if-true, if-false). =VLOOKUP finds value in table. =PMT calculates loan / annuity payment.

Worked Example — Total: Claims C2:C4 = 12000, 18000, 15000. Formula =SUM(C2:C4). Computer: 12000 + 18000 + 15000 = 45000. You write formula, not just 45000.

Worked Example — Average: Premiums 2000, 3000, 5000. Sum = 10000. Count = 3. Average = 100003 = 3333.33. Formula: =AVERAGE(B2:B4).

Good practice: Label every column. Keep inputs, calculations, results separate. Check totals by second method. If result looks impossible — e.g. average higher than highest — it is wrong.

Common exam mistake: Writing answer without formula. In spreadsheet questions, formula IS the answer.

Topic 4: Actuarial Software and Programming Basics

Estimated time: ~30 minutes  |  Objectives: Explain actuarial software, explain Input → Process → Output, explain why software beats hand calc, write steps, choose right tool.

Actuaries use Excel, R, Python, and specialist systems like Prophet or MoSes. A program is a list of clear steps computer follows exactly, every time, without getting tired.

Input → Process → Output: Input = what you give (age, sum assured). Process = what it does (premium = sum × rate). Output = what you get (premium). If input is wrong, output is wrong. That is "Garbage In, Garbage Out".

Why software beats hand: Speed — 100,000 policies in seconds. Consistency — same steps every time. What-if — change rate 0.02 to 0.03, press Enter, all update. Audit — you can check steps and re-run.

Worked Example: Premium for one policy. Step 1: Input sum = 100,000, rate = 0.02. Step 2: Process: premium = 100,000 × 0.02 = 2,000. Step 3: Output: premium = 2,000. In Python: premium = 100000 * 0.02. Actuary decided rate. Computer just multiplied.

Choosing tool: Spreadsheet — quick checks, small models. R / Python — large data, repeating calc, graphs. Specialist software — full company models, reserves, solvency.

Common exam mistake: Saying software "decides" premium. Software does not decide. Actuary decides method, assumptions, rate. Software only follows them.

Topic 5: Data Security, Ethics and Privacy

Estimated time: ~30 minutes  |  Objectives: Define security, privacy, ethics, list ways to protect data, judge real situation, explain what to do when asked for data you should not share.

Actuarial data is sensitive: names, ages, health, money, ID numbers. Security = protecting from loss / theft. Privacy = only collecting / using what you need. Ethics = using fairly, even when you could get away with unfair use.

  1. Passwords + access control — only staff who need data can open it.
  2. Backup — copy in another safe place, so if computer dies, data lives.
  3. Do not share / download to personal phone / WhatsApp — work inside system.
  4. Encryption — scramble data so thief cannot read without key.
  5. Updates + antivirus — keep software updated, do not open suspicious links.

Ethics in practice: Collect only what you need. Use only for purpose person agreed to. Do not use health data to refuse unfairly. Do not sell client lists. Keep record of who accessed what. If unsure, ask manager — do not guess.

Worked Example: Clerk shares client list on WhatsApp to "work from home". That is breach — even if nothing bad happens yet. Right way: access system with password, no download, no sharing, work inside system.

Another Example: Colleague asks for client's health data "just to check". Correct answer is No. No permission for that purpose. Right way: colleague asks manager, manager checks if access is needed, gives limited access through system, with record.

Common exam mistake: Listing "password" and stopping. Always give method + what it protects against.

Topic 6: Management Information Systems and Decision Support

Estimated time: ~30 minutes  |  Objectives: Define MIS, distinguish raw data vs MIS report, explain good report, calculate profit, explain Decision Support / what-if.

A Management Information System turns raw data into reports for managers. Raw data = 100,000 rows, too many to read. MIS report = one page: total premiums, total claims, profit, new policies, claims.

Good MIS report: Accurate — numbers correct. Timely — late report is useless. Clear — one page, labelled. Relevant — only what that manager needs. Comparable — this month vs last month, so manager sees trend.

Decision Support / what-if: Manager asks "What if...?" System recalculates. Example: "What if claims rise 10%?" New claims = old × 1.10, new profit = premiums − new claims.

Worked Example — Profit: Premiums = 14,500,000, Claims = 10,000,000. Profit = Premiums − Claims = 14,500,000 − 10,000,000 = 4,500,000. Formula: Profit = Total Premiums − Total Claims.

Worked Example — Raw vs Report: Raw: 100,000 rows, each one policy. Report: 5 lines — Total Policies: 100,000, Total Premiums: 20,000,000, Total Claims: 12,000,000, Profit: 8,000,000, New Policies This Month: 500. Raw = detail, MIS = summary for decision.

Common exam mistake: Saying MIS is "a report". MIS is the system that produces the report. Report is output.
