Topic 1: Introduction to Information Systems - Start From Zero

What: An Information System is people + data + software + hardware + procedures working together to turn data into information for decisions.

Why: An insurer without a system cannot know who is insured, who paid, who claimed. It would guess. Systems stop guessing.

Data → Processing → Information → Decision

Example: Policy data (age, sum assured) → System calculates premium → Manager sees report → Decides premium rate

Worked Example: A company has 1,000 policies on paper. Finding one policy takes 30 minutes. After a system, it takes 10 seconds. The system did not change the data — it changed how fast you can use it.

Topic 2: Data, Databases and Data Management - Start From Zero

What: A Database is organised data you can search, update, and protect. A table = rows (records) + columns (fields). Key = unique ID for each record, e.g. Policy Number.

Why: If two people have the same name, name cannot be the key. Policy Number can. Without a key, you pay the wrong person.

Table: Policies | Columns: PolicyNo (Key), Name, Age, SumAssured, Premium | Row = one policy

Worked Example: Table has 500 rows. You search PolicyNo = P-102. System returns 1 row in seconds. That is a database — not a list in a notebook.

Topic 3: Spreadsheets for Actuaries - Start From Zero

What: Spreadsheets (Excel / Google Sheets) are the actuary's daily tool for calculations, tables, and checks.

Why: Before expensive software, actuaries test ideas in a spreadsheet. If the spreadsheet is wrong, the premium is wrong.

Key formulas: =SUM, =AVERAGE, =IF, =VLOOKUP, =PMT. Always use cell references, never type numbers inside a formula.

Worked Example: Premiums in B2:B5 are 2500, 5000, 3000, 4000. Total = =SUM(B2:B5) = 14,500. If you type =2500+5000+3000+4000, and one premium changes, your answer stays wrong. With =SUM, it updates.

Topic 4: Actuarial Software and Programming Basics - Start From Zero

What: Actuaries use software like Excel, R, Python, and actuarial systems (e.g. Prophet, MoSes) to model many policies at once. Programming = giving the computer clear steps.

Why: You cannot calculate 100,000 policies by hand. A program does it in seconds, the same way every time.

Program logic: Input → Process → Output. Example: Input age, sum assured → Process: premium = sum × rate → Output: premium.

Worked Example: In Python: premium = 100000 * 0.02 → premium = 2000. The computer did not decide 0.02 — the actuary did. The computer just followed the step.

Topic 5: Data Security, Ethics and Privacy - Start From Zero

What: Actuarial data is sensitive: names, ages, health, money. Security = protect it. Ethics = use it fairly. Privacy = only use what you need, only who needs it.

Why: If policy data leaks, people lose money and trust. If you use health data to refuse someone unfairly, that is unethical, even if the computer allowed it.

Rules: Passwords + Access control + Backup + Do not share + Do not use data for a purpose the person did not agree to.

Topic 6: Management Information Systems and Decision Support - Start From Zero

What: MIS = reports from the system that help managers decide. Decision Support = what-if: "What if claims rise 10%? What happens to profit?"

Why: A manager does not read 100,000 rows. They read one report: total premiums, total claims, profit. That report must be correct.

Report example: Total Premiums - Total Claims = Profit. If premiums 14,500,000 and claims 10,000,000, profit = 4,500,000.

Worked Example: Report shows claims rising. Manager asks: "What if claims rise 10% next year?" System recalculates: new claims = 11,000,000, new profit = 3,500,000. Manager decides to review premiums. That is decision support.
